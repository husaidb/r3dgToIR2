# L2 金属先验：完整训练流程

本文给出从原始数据到阶段二结束的全部命令，适用于**自采 MWIR 数据**（Blender 格式，非 COLMAP、非合成数据集）。
重光照评测不在本文范围（评测脚本暂不使用）。

案例假设：

```
/data/mwir/scenes/kettle/
```

场景内容：一只不锈钢水壶放在木桌上，100 个红外视角。

---

## 0. 总览

```
① 数据检查（transforms json、图片、points3d.ply）
② 每视角前景 mask（可选，可用 generate_masks.py）
③ 阶段一：python train.py -t render   → chkpnt30000.pth
④ 物体级 metalness（可选）：可见光照片 → VLM → scene_meta.json
⑤ prepare_object_metalness.py（需要 ③ 的 ckpt）→ metal_prob.npy
⑥ 阶段二：python train.py -t neilf    → 材质 + 光照
```

②④⑤ 只在物体是金属（`m_obj > 0`）时需要。若按非金属处理（`m=0`），可以完全跳过，阶段二也不要传 `--material_prob_path`——效果与旧代码逐位一致。

---

## 1. 数据目录准备

```
/data/mwir/scenes/kettle/
├── transforms_train.json      # 必填
├── points3d.ply               # 必填（初始点云）
├── train/                     # 红外图，与 json 的 file_path 对应
│   ├── 0001.png
│   ├── 0002.png
│   └── ...
├── masks_ir/                  # 可选：每视角前景 mask（步骤 ③）
│   ├── 0001.png
│   └── ...
├── visible/                   # 可选：可见光照片（步骤 ②）
│   ├── IMG_0001.jpg
│   └── ...
└── scene_meta.json            # 可选：步骤 ② 的产物
```

`transforms_train.json` 的最小内容：

```json
{
  "camera_angle_x": 0.6911,
  "frames": [
    {"file_path": "train/0001", "transform_matrix": [[...], [...], [...], [...] ]},
    {"file_path": "train/0002", "transform_matrix": [[...], [...], [...], [...] ]}
  ]
}
```

### 三个必查的坑

1. **`file_path` 必须用正斜杠 `train/0001`**。Windows 下写成 `train\0001` 也能跑，但在 Linux 服务器上反斜杠会被当成文件名的一部分，直接读不到图。
2. **`points3d.ply` 必须存在**。缺失时 `scene/dataset_readers.py` 会随机生成 10 万个点，重建基本不成形。
3. **不需要 `transforms_test.json` 和 `test/`**——本文不跑评测脚本。只有 Blender 读取器 + `--eval` 时才会去读它们。

`visible/` 与 `train/` 同级即可，**不需要与训练视角一一对应**：VLM 只给物体级标量，脚本默认均匀抽 6 张照片。

## 2. 物体级 metalness（可选）

### 方案 A：手动指定（最简单）

已知物体是金属时，不跑 VLM，直接在 §3 的 `prepare_object_metalness.py` 命令里传 `--metallic 0.9`。

建议用 0.8~0.9 而非 1.0：金属表面常有氧化和粗糙度差异，略低于 1 更稳。

注意 `train.py` 也有一个同名 `--metallic`，那是**全局标量**，会作用于包括桌面在内的所有高斯；本流程不用它，只用 §3 的物体级版本。

### 方案 B：可见光照片 + VLM（自动）

```bash
cd /data/mwir/3dgs/Relightable3DGaussian
python script/query_vlm_metalness.py \
  -s /data/mwir/scenes/kettle \
  --model qwen3-vl-flash
```

- API key：填脚本顶部 `API_KEY = "sk-..."`，或设置环境变量 `DASHSCOPE_API_KEY`
- 模型：默认 `qwen3-vl-flash`（便宜）；判错时可换 `qwen3-vl-plus`
- 产物：`/data/mwir/scenes/kettle/scene_meta.json`

```json
{
  "object": "不锈钢水壶",
  "metallic": 0.86,
  "source": "rgb_vlm:qwen3-vl-flash",
  "confidence": 0.82,
  "...": "..."
}
```

- 没有 `visible/` 目录：写出 `"source": "no_visible_photos", "metallic": 0.0` 并打印 WARN——表示**没有启用金属先验**，不是"判定为非金属"。
- 所有 API 调用失败：脚本报错退出，**不写文件**（断网不会被当成非金属）。
- `confidence < 0.5`：先人工看一眼照片再决定是否采用。

先花 0 元检查请求构造：

```bash
python script/query_vlm_metalness.py -s /data/mwir/scenes/kettle --dry_run
```

## 3. 生成 metal_prob.npy

前提：已有每视角 mask，文件名与训练图同名（`masks_ir/0001.png` 对应 `train/0001.png`），前景=1、背景=0。
mask 只勾**目标物体**（水壶），不要勾桌子；边界建议 `--erode 3`。桌面场景**不要**加 `--fill_bbox`。

### 用 `generate_masks.py` 自动生成 mask

仓库根目录的 `generate_masks.py` 用 rembg 抠图，输出 alpha 通道作为 mask：

```bash
cd /data/mwir/3dgs/Relightable3DGaussian
# 该脚本写死读取 <scene>/images/、写出 <scene>/masks/；数据在 train/ 时先建软链接（Linux）
ln -s /data/mwir/scenes/kettle/train /data/mwir/scenes/kettle/images
python generate_masks.py -s /data/mwir/scenes/kettle
```

- 之后 `--masks_dir` 用 `/data/mwir/scenes/kettle/masks`
- rembg 的模型是在**可见光**照片上训练的，热红外图对比度低时可能抠不干净。先跑完抽看几张，缺的用标注工具补
- Windows 下没有 `ln`：直接修改脚本里的 `"images"` / `"masks"` 两个字符串，或在数据分析目录里复制一份

```bash
cd /data/mwir/3dgs/Relightable3DGaussian
python script/prepare_object_metalness.py \
  -s /data/mwir/scenes/kettle \
  -m /data/mwir/output/kettle_render \
  --checkpoint /data/mwir/output/kettle_render/chkpnt30000.pth \
  --masks_dir /data/mwir/scenes/kettle/masks_ir \
  --scene_meta /data/mwir/scenes/kettle/scene_meta.json \
  --erode 3
```

注意：

- 该步骤要加载**阶段一训练完成后的 checkpoint**，所以必须在 §4 阶段一之后运行。
- `-m` 传阶段一的输出目录（脚本会往里面写 `input.ply`/`cameras.json`，不会破坏 checkpoint）。
- 手动指定 metalness 时把 `--scene_meta ...` 换成 `--metallic 0.9`。
- 产物：`/data/mwir/scenes/kettle/material_prior/{object_prob.npy, metal_prob.npy, metal_prior_stats.json}`。

先检查统计：

```bash
python - <<'EOF'
import json
s = json.load(open("/data/mwir/scenes/kettle/material_prior/metal_prior_stats.json"))
print(s["num_gaussians"], s["observed_ratio"], s["object_ratio_at_thresh"])
EOF
```

`object_ratio_at_thresh`：水壶场景通常 1%~30%。>50% 基本是桌子被勾进 mask 了；≈0 说明文件名/相机对不上。

## 4. 阶段一：几何 + 表观

```bash
cd /data/mwir/3dgs/Relightable3DGaussian
python train.py \
  -s /data/mwir/scenes/kettle \
  -m /data/mwir/output/kettle_render \
  -t render \
  --lambda_depth 0 \
  --lambda_depth_smooth 0 \
  --lambda_depth_var 0 \
  --lambda_mask_entropy 0 \
  --lambda_opacity 0 \
  --lambda_surface 0 \
  --lambda_scaling 0 \
  --lambda_normal_render_depth 0 \
  --lambda_normal_mvs_depth 0 \
  --lambda_normal_smooth 0 \
  --lambda_point_entropy 0 \
  --lambda_orientation 0
```

- 这些细节/几何正则项**全部为 0**（本来也是默认值，显式写出是为了防止你自己的启动脚本或历史配置把它们打开）。自采数据上深度、法线、朝向监督通常不可靠，打开后反而把重建拉垮。
- **保留**核心损失：`lambda_dssim=0.2`（L1 + SSIM），不加参数即默认。
- **不要**把几何学习率设 0，也不要关掉 densify——阶段一就是靠它们把点云长成物体形状。默认 `--iterations 30000`、`--densify_until_iter 10000` 即可。
- 显存不够时加 `--resolution 2`（长边减半）。

产物（在 `-m` 目录下）：

```
chkpnt30000.pth          # 阶段二要用
point_cloud/iteration_30000/point_cloud.ply
```

> 代价：法线 `_normal` 没有任何损失监督，基本不可用。阶段二 BRDF 使用的正是这个法线，金属高光方向可能偏。这是用户确认过、可接受的取舍；如果阶段二着色明显不对，再回头给阶段一加小的 `--lambda_normal_render_depth`（例如 0.05）单独试。

## 5. 阶段二：材质 + 光照

```bash
cd /data/mwir/3dgs/Relightable3DGaussian
python train.py \
  -s /data/mwir/scenes/kettle \
  -m /data/mwir/output/kettle_neilf \
  -t neilf \
  --checkpoint /data/mwir/output/kettle_render/chkpnt30000.pth \
  --material_prob_path /data/mwir/scenes/kettle/material_prior/metal_prob.npy \
  --emissivity_mode lut \
  --temperature 30 \
  --densify_until_iter 0 \
  --position_lr_init 0 \
  --position_lr_final 0 \
  --normal_lr 0 \
  --rotation_lr 0 \
  --scaling_lr 0 \
  --opacity_lr 0 \
  --sh_lr 0 \
  --lambda_depth 0 \
  --lambda_depth_smooth 0 \
  --lambda_mask_entropy 0 \
  --lambda_opacity 0 \
  --lambda_surface 0 \
  --lambda_normal_render_depth 0 \
  --lambda_normal_smooth 0 \
  --lambda_point_entropy 0 \
  --lambda_orientation 0 \
  --lambda_depth_var 0 \
  --lambda_scaling 0 \
  --lambda_light 0 \
  --lambda_base_color 0 \
  --lambda_base_color_smooth 0 \
  --lambda_roughness_smooth 0 \
  --lambda_light_smooth 0 \
  --lambda_visibility 0 \
  --lambda_visibility_smooth 0 \
  --lambda_env_smooth 0 \
  --lambda_emission_constraint 0
```

说明：

- **几何全部冻结**：位置/法线/旋转/缩放/不透明度/SH 学习率 0，`--densify_until_iter 0` 关闭增密与不透明度重置。阶段二只学 `base_color`、`roughness`、可见性、入射光与环境光。
- `--temperature 30` 换成你实测/设定的**物体温度（摄氏度）**。不传则热辐射项不存在，`lut` 发射率不会进入渲染方程。
- `--emissivity_mode lut` 是主实验设置；`analytic`/`auto` 只作消融。
- 没有金属先验（`m=0`）：**删掉 `--material_prob_path` 这一行**即可；不要改脚本。
- 不要同时传 `--metallic` 和 `--material_prob_path`（npy 优先，标量会被忽略）。
- `-m` 不能和阶段一相同，否则 checkpoint 会互相覆盖。

## 6. 参数为 0 的完整清单（便于复制）

阶段一（几何正则）：

```
--lambda_depth --lambda_depth_smooth --lambda_depth_var --lambda_mask_entropy
--lambda_opacity --lambda_surface --lambda_scaling
--lambda_normal_render_depth --lambda_normal_mvs_depth --lambda_normal_smooth
--lambda_point_entropy --lambda_orientation
```

阶段二额外（冻结几何 + PBR 正则）：

```
--densify_until_iter 0
--position_lr_init 0 --position_lr_final 0 --normal_lr 0
--rotation_lr 0 --scaling_lr 0 --opacity_lr 0 --sh_lr 0
--lambda_light 0 --lambda_base_color 0 --lambda_base_color_smooth 0
--lambda_roughness_smooth 0 --lambda_light_smooth 0
--lambda_visibility 0 --lambda_visibility_smooth 0
--lambda_env_smooth 0 --lambda_emission_constraint 0
```

保持非 0：`--lambda_dssim 0.2`（默认）、`--lambda_pbr 1`（默认）。

## 7. 训练后检查

1. **TensorBoard**：`tensorboard --logdir /data/mwir/output/kettle_render`，看 `train_loss_patches/psnr` 是否正常上升。
2. **metalness 是否真的传进去了**：阶段二日志/可视化里物体区域应为 `m≈0.9`，背景为 0。若物体也是 0，检查 npy 路径与点数。
3. **ε 直方图**：`lut` 模式下 `ε = 1 − [(1−m)·base_color + F0·A + B]`，`F0 = 0.04(1−m) + m·base_color`。
   - 金属要出现低 ε，前提是 `base_color` 被学高；`base_color` 有 0.8 上限，抛光金属的 0.03~0.05 达不到，这是模型限制，不是 bug。
   - **不要**用"物体 ε 必低于背景"做验收：相同 base_color 下介电 ρ 比金属 ρ 多 `bc(1−A)+0.04A>0`，介电反而 ε 更低。
4. **法线**：本流程下阶段一法线无监督，属已知取舍，见第 4 节说明。

## 8. 常见报错

| 现象 | 原因 | 处理 |
|---|---|---|
| `metal_prob length ... != num gaussians` | npy 与 checkpoint 点数/顺序不一致 | 必须用生成 npy 时的同一份阶段一 ckpt；阶段二 `--densify_until_iter 0` |
| 读图失败、路径含 `\` | json 用了 Windows 反斜杠 | 改成 `train/0001` |
| 重建不成形、点云不收敛 | 缺 `points3d.ply`，或打开了别的几何正则 | 补齐点云；确认第 6 节参数为 0 |
| 发热辐射项没生效 | 没传 `--temperature`，或 `--emissivity_mode external` | 同时给 `--temperature` 和 `--emissivity_mode lut` |
| 桌面被当成金属 | mask 勾了整片前景 | 只勾目标物体，`--erode 3`，看 `object_ratio_at_thresh` |
| 评测脚本报 `NotImplementedError` | 自采场景不在硬编码列表 | 评测时传 `--base_color_scale`（本文不涉及） |

## 9. Linux 一条龙

```bash
set -e
SCENE=/data/mwir/scenes/kettle
OUT=/data/mwir/output
cd /data/mwir/3dgs/Relightable3DGaussian

# 阶段一
python train.py -s $SCENE -m $OUT/kettle_render -t render \
  --lambda_depth 0 --lambda_depth_smooth 0 --lambda_depth_var 0 \
  --lambda_mask_entropy 0 --lambda_opacity 0 --lambda_surface 0 --lambda_scaling 0 \
  --lambda_normal_render_depth 0 --lambda_normal_mvs_depth 0 \
  --lambda_normal_smooth 0 --lambda_point_entropy 0 --lambda_orientation 0

# 金属先验（有可见光照片时）
python script/query_vlm_metalness.py -s $SCENE --model qwen3-vl-flash
python script/prepare_object_metalness.py \
  -s $SCENE -m $OUT/kettle_render \
  --checkpoint $OUT/kettle_render/chkpnt30000.pth \
  --masks_dir $SCENE/masks_ir \
  --scene_meta $SCENE/scene_meta.json --erode 3

# 阶段二
python train.py -s $SCENE -m $OUT/kettle_neilf -t neilf \
  --checkpoint $OUT/kettle_render/chkpnt30000.pth \
  --material_prob_path $SCENE/material_prior/metal_prob.npy \
  --emissivity_mode lut --temperature 30 \
  --densify_until_iter 0 \
  --position_lr_init 0 --position_lr_final 0 --normal_lr 0 \
  --rotation_lr 0 --scaling_lr 0 --opacity_lr 0 --sh_lr 0 \
  --lambda_depth 0 --lambda_depth_smooth 0 --lambda_mask_entropy 0 \
  --lambda_opacity 0 --lambda_surface 0 --lambda_normal_render_depth 0 \
  --lambda_normal_smooth 0 --lambda_point_entropy 0 --lambda_orientation 0 \
  --lambda_depth_var 0 --lambda_scaling 0 \
  --lambda_light 0 --lambda_base_color 0 --lambda_base_color_smooth 0 \
  --lambda_roughness_smooth 0 --lambda_light_smooth 0 \
  --lambda_visibility 0 --lambda_visibility_smooth 0 \
  --lambda_env_smooth 0 --lambda_emission_constraint 0
```

无可见光照片（`m=0`）时：跳过 `query_vlm_metalness.py` 和 `prepare_object_metalness.py`，阶段二删掉 `--material_prob_path` 一行。
